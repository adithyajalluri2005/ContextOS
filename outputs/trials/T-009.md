# T-009: trial with a real agent

Date: 2026-11-12. Claude Code 2.1.322, non-interactive (`claude -p`), on Windows 11.

## Setup

- A temporary MCP config (`--mcp-config ... --strict-mcp-config`) started `contextos mcp`
  from the repo venv. The user's own Claude Code settings were not changed.
- `CONTEXTOS_HOME` pointed to a throwaway folder in the session scratchpad, not `~/.contextos`.
- Chat A ran in folder `workA`, chat B in a separate empty folder `workB`. They had no shared memory.
- All chats were made up ("scaleit" recipe tool, "birdlog" staging server). All keys were fake.

## Problems found

1. **Bug (from T-008): `contextos list` and `contextos show` crash on Windows when their output
   is sent to a file or a pipe** and a context has characters outside the Windows cp1252 set
   (for example Japanese or emoji): `UnicodeEncodeError: 'charmap' codec can't encode characters`.
   Characters that cp1252 has, like the dash in a title, come out as the wrong byte (`\x96`)
   instead of UTF-8. In a normal terminal window it works. The MCP server is not affected (the
   agents loaded and saved without problems).
   Fix idea: make the command line write UTF-8 (for example `sys.stdout.reconfigure(encoding="utf-8")`
   at start-up) and add a test that sends non-English text through `list` and `show`.
   Outside T-009 scope (`contextos/cli.py`); proposed as the next task.

2. **Over-hiding: `user@host` inside a URL is treated as an email.** In one field the agent wrote
   the URL without the password, and the email rule replaced `admin@db.birdlog.example`, so the
   host name was lost: `postgres://[hidden: email]:5432/birds`. Safe (it hides too much, not too
   little), but the next agent loses the host name. Fix idea: do not treat `user@host` right after
   `://` as an email. Lower priority.
